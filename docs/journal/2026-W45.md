# 2026-W45

## Built

Set up the project with tooling before writing any payment code.

- **uv for everything.** `pyproject.toml` with Python 3.15 and dev tools in a
  `[dependency-groups]` table instead of a separate `requirements-dev.txt`.
  `uv.lock` is the source of truth; `requirements.txt` is exported from it for
  tools that don't speak uv.
- **Ruff for lint and format, pinned to 0.17.3.** Lint uses the preview rule
  groups (`correctness`, `suspicious`, `complexity`, `performance`, `style`,
  `security`) plus a few rules picked for payments code: `DTZ` (no naive
  datetimes), `BLE001` (no blind `except Exception`), `ASYNC` (asyncio
  pitfalls), `T201` (no `print` in library code). `S311` is ignored on
  purpose: seeded `random.Random` is how fault plans stay reproducible.
- **mypy in strict mode** on `src/`.
- **pytest with pytest-asyncio and Hypothesis.** asyncio in strict mode,
  function-scoped event loops, so tests can't leak loop state into each other.
- **One Makefile as the entry point.** `make lint`, `make typecheck`,
  `make test`, `make check`. CI calls the same targets, so local and CI can't
  drift apart.
- **pre-commit hooks.** Ruff check (with `--fix`) and ruff format from the
  official hook repo; mypy as a local hook through `uv run mypy`, so it type
  checks against the project's real environment instead of an isolated one
  with no dependencies installed.
- **GitHub Actions CI**, with a status badge in the README:
  - actions pinned to commit SHAs, not tags
  - `permissions: contents: read` and `persist-credentials: false`
  - `concurrency` cancels superseded runs on the same ref
  - 15 minute timeout
  - `uv sync --locked` fails the build if `uv.lock` is stale
  - `RUFF_OUTPUT_FORMAT=github` turns lint errors into inline PR annotations

## Learned

- Ruff's formatter doesn't sort imports. You need the `I` lint rules for that.
- The Ruff version is pinned in two places, `pyproject.toml` and
  `.pre-commit-config.yaml`, and nothing keeps them in sync except a comment.
- An action pinned to a tag can change under you, because tags can be moved.
  A SHA can't.
